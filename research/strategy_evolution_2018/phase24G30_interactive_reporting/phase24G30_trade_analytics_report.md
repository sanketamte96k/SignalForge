# SignalForge — Phase 24G.30: Trade Analytics Report

## 1. Trade History Data Contract

Every simulated trade recorded by the SignalForge backtest engine adheres to a strict data schema. The trade analysis table exposes all supplied fields without fabricating missing data:

| Field Name | Type | Unit / Format | Description |
| :--- | :--- | :--- | :--- |
| `trade_id` | Integer | Serial `#` | Sequential 1-based chronological trade index. |
| `symbol` | String | Uppercase | Trading instrument symbol (e.g. `NIFTY 50`, `ADANIPORTS`). |
| `side` | String | `BUY` / `SELL` | Order direction / position side. |
| `entry_time` | String | `YYYY-MM-DD HH:MM:SS` | Timestamp of bar execution on trade entry. |
| `entry_price` | Float | ₹ (INR) | Executed entry price per unit. |
| `exit_time` | String | `YYYY-MM-DD HH:MM:SS` | Timestamp of bar execution on trade exit. |
| `exit_price` | Float | ₹ (INR) | Executed exit price per unit. |
| `quantity` | Integer | Units | Filled unit size (e.g. 1 index unit or share). |
| `gross_pnl` | Float | ₹ (INR) | Pre-fee trade P&L: `(exit_price - entry_price) * qty * direction`. |
| `costs` | Float | ₹ (INR) | Aggregate statutory fees, turnover tax, and slippage. |
| `net_pnl` | Float | ₹ (INR) | Realized net trade return: `gross_pnl - costs`. |
| `return_pct` | Float | % | Percentage return relative to entry notional: `(net_pnl / (entry_price * qty)) * 100`. |
| `exit_reason` | String | Category | Rule triggering trade exit (e.g. `TAKE_PROFIT`, `STOP_LOSS`, `TIME_EXIT`). |

## 2. Interactive Filtering and Sorting Specification

### Immutable Filtering Logic
Filtering acts purely on the presentation layer, preserving the underlying trade data array untouched:
- **`ALL`:** Displays all $N$ completed trades.
- **`WINNERS`:** Filters for trades where `net_pnl > 0.0`.
- **`LOSERS`:** Filters for trades where `net_pnl < 0.0`.
- **`LONG / BUY`:** Filters for trades where `side.toUpperCase().includes('BUY')` or `side.toUpperCase().includes('LONG')`.
- **`SHORT / SELL`:** Filters for trades where `side.toUpperCase().includes('SELL')` or `side.toUpperCase().includes('SHORT')`.

### Sorting Logic
Sorting operates on a detached copy (`[...trades].sort(...)`), leaving original array indices intact:
- **Date / Trade # (Ascending):** `(a.trade_id || 0) - (b.trade_id || 0)` (Chronological default).
- **Date / Trade # (Descending):** `(b.trade_id || 0) - (a.trade_id || 0)` (Reverse chronological).
- **Net P&L (Descending):** `b.net_pnl - a.net_pnl` (Largest wins first).
- **Net P&L (Ascending):** `a.net_pnl - b.net_pnl` (Largest losses first).
- **Return % (Descending):** `b.return_pct - a.return_pct` (Highest percentage return first).
- **Return % (Ascending):** `a.return_pct - b.return_pct` (Lowest percentage return first).
